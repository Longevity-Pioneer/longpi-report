# narrative.json 写法

narrative.json 是报告里 Claude 写的部分。数字一律从 `facts` 事实表和 results.json 抄，不自己算、不改。
示例：`examples/demo_narrative.json`。所有字段都可省略，省略的模块不显示或由脚本给默认内容。

## 字段

| 字段 | 内容 | 要求 |
|---|---|---|
| `summary` | 总览顶部一段话 | 2–3 句：LongPi Age（与事实表一致，保留 1 位小数）、比日历年龄年轻/年长几岁、主要加分项和扣分项、最值得做的三件事 |
| `top3` | 本季度三件事（字符串数组） | 一般省略，脚本自动取非处方、证据 A/B、预期效果最大的三项 |
| `clinical` | 临床待办 `[{action, due}]` | 需要医生参与的事；`due` 写"尽快"或"YYYY-MM" |
| `risks` | 风险卡 | 见下 |
| `pgx`、`pgx_note` | 药物基因组条目（字符串）和说明 | 见 `pgx_rules.md`；没有基因数据就省略 |
| `pheno_note` | PhenoAge 图的说明（一句话） | 讲趋势和同步变化的指标 |
| `organs_note` | 器官甲基化图的说明 | 一般省略（脚本自动生成，含"不计入 LongPi Age"） |
| `frontier` | 前沿分析卡 `[{title, grade, body, next}]` | 4–6 张；`grade` 用"成熟""探索"或"成熟/探索" |
| `quality_issues` | 已知数据问题（字符串数组） | 设备估算、数据断档、测量不规范、缺项 |
| `data_value_note` | 总览页"让结果更准"的一两句话（可选） | 先肯定已有资料让区间缩了多少，再点名最值得补的一项；数字只用事实表"让结果更准"里的 |
| `gaps` | 补测清单之外、不改变 LongPi Age 但有用的检查 `[[项目, 用处]]`（可选） | 例如 ApoB、Lp(a)；补测清单本身由脚本生成，不要在这里重复或改写 |
| `data_notes` | 各图的说明 `{coverage, sleep, rhr, steps, cgm}` | 一两句，说清图上看什么 |
| `n_of_1` | N-of-1 实验 `{title, subtitle, rows: [[项, 内容]]}` | 选一个能在家测量结局、效果快的干预（血压最常用） |
| `asks` | 请用户补充的资料（建议每份报告都写） | 显示在总览页；主动提醒拍照、量腰围、测握力、家庭血压、饮食记录、复查抽血等，见下 |
| `supplements` | 补充剂与需先检查的项目（可选，建议都写） | 分组卡片：非处方补充剂、需先诊断、处方药（只讲证据）；另列不建议花钱的。见下 |
| `training` | 训练方案（可选） | 用户要具体运动计划时写；显示在干预页 N-of-1 下方，见下 |
| `banner`、`footer` | 页面横幅、页脚补充 | 一般省略 |

## 风险卡 `risks[]`

```json
{"name": "血压偏高", "level": "关注", "todo": true,
 "drivers": ["……"], "protect": ["……"],
 "evidence": "中国高血压防治指南（2024 年修订版）：……",
 "action": "……", "due": "尽快"}
```

- `level` 只能是"关注""留意""一般"，分级规则见 `risk_rules.md`。
- `drivers`、`protect` 写具体数值和日期，比如"体检收缩压 124 → 131 → 136 → 133 mmHg（2023–2026）"。
- `evidence` 写到具体指南或研究；脚本算好的临床指标在 results.json 的 `clinical` 里（China-PAR、eGFR、FIB-4、中心型肥胖、尿酸、LDL 分档）。
- 没有经过中国人群校准的绝对概率不要写（China-PAR 例外，它是中国人群模型）。
- 不写"确诊为……"；写"提示""接近诊断线""建议就医评估"。
- 每张卡都有可执行的下一步和时间。

建议顺序：先"关注"，再"留意"，最后"一般"；同级按严重程度。

## 前沿卡 `frontier[]`

- 只描述 results.json 里真实存在的数据：PhenoAge 轨迹、甲基化与器官年龄、VO2max/静息心率/HRV 趋势、餐后血糖（`data.cgm_meals`）、家庭血压早晚差、步数历史。
- 相关性只在数据里真的算过时才写，并注明"相关，不等于因果"。
- 讲变化时对照噪声：PhenoAge 两次相差超过 1.96×√2×单次波动才算确定的变化；还在波动内就说"方向在变好，接近但还没超出正常波动"，并给复测时间。
- `next` 写一个具体的下一步。

## 文字要求

- 标题（风险卡名、前沿卡标题、各模块和分组标题、动作名）用简洁书面语，如“心肺适能变化趋势”“饮食配合”，不用“在往上走”“怎么配合”这类口语；正文仍写给普通人看。
- 写给普通人看：短句、先结论；第一次出现的专业词用括号解释（如"心肺运动试验（CPET）"）。
- 读起来要像中国人自然说的话，避免翻译腔；不用"赋能""闭环"之类的词。
- 不出现脚本名、参数名、"Monte Carlo"、"MCP"等后台术语（`render` 会检查）。
- 鼓励要具体："静息心率从 69 降到 64，这是训练起效的典型样子"，不要空泛地夸。
- 模型估计称"AI 预测"即可，不叠加免责声明。

## 训练方案 `training`（可选）

```json
{"title": "...", "subtitle": "...",
 "blocks": [{"title": "...", "sub": "...", "header": ["列1","列2"], "table": [["行","值"]], "steps": ["..."], "list": ["..."], "text": "..."}],
 "sessions": [{"name": "力量 A", "sub": "...", "exercises": [
   {"name": "高脚杯深蹲", "alias": "一句话说清是什么", "target": "练到哪里", "dose": "3 组 × 10–12 次",
    "images": ["exercise_img/Goblet_Squat_0.jpg", "exercise_img/Goblet_Squat_1.jpg"],
    "steps": ["..."], "cues": ["..."], "mistakes": ["..."], "easier": "...", "harder": "..."}]}],
 "credit": "图片来源"}
```

- **优先引用内置动作库**：`{"ref": "goblet_squat", "dose": "3 组 × 8–10 次"}`。名称、说明、步骤、要点、常见错误、降阶、进阶和起止两张照片都从 `data/exercise_library.json` 自动带出，写在这里的字段会覆盖库里的值（通常只写 `dose`）。可用的 id 见事实表"动作库"一节；未知 id 会被叙述检查拦下。
- 动作库里没有的动作才手写全部字段：`images` 写相对 narrative.json 的路径，`render` 会内嵌进 HTML（单文件、离线可开）；第一张标"起始"，第二张标"结束"（可用 `captions` 改）。图片可用 Free Exercise DB（github.com/yuhonas/free-exercise-db，公共领域）：`exercises/<id>/0.jpg`、`1.jpg`，缩到约 460 px 宽，并在 `credit` 注明来源。常用的新动作可以加进动作库（`evidence/scripts/build_exercise_library.py`）。
- 按用户现有运动量定起点：事实表"可穿戴摘要"里的 `workouts_90d` 是近 90 天手表记录的运动次数和分钟数。
- 强度、周安排、进阶都写成具体数字（心率区间、组数次数、起始重量、加重规则），并写清停止运动的警示症状。

## 补充剂 `supplements`

```json
{"title": "...", "subtitle": "...",
 "groups": [{"name": "可以直接开始", "sub": "...", "items": [
   {"name": "肌酸", "tier": "非处方", "why": "为什么适合这个人（引用他的数据）", "dose": "每天 3–5 克", "upper": "...", "trial": "试用多久、看什么指标", "avoid": "禁忌", "evidence": "研究或指南"}]}],
 "skip": [["NMN", "为什么不建议"]], "note": "..."}
```

按档写：非处方给常用量、上限、试用期和禁忌；探索级（有人体试验、或可信机制加动物研究，指南还没收）也写，`tier` 标明证据类型（如“探索 · 动物研究 + 小型人体试验”），`trial` 写成个人实验：先 2 周基线、一次只加一种、8–12 周、看哪几个他自己能测的指标，避免和刚开始的运动/减重混在一起；需要先诊断的（铁剂等）写查什么、看哪个科；处方药只讲证据和医生会考虑什么，不给剂量。每一条都要和这个人的数据挂钩。

## 请用户补充的资料 `asks`

每份报告都要主动告诉用户下一步还能补什么，别等用户问。脚本已生成一份默认清单（结果里的 `asks_default`，事实表"默认待补充资料"），narrative 不写 `asks` 时报告显示这份；要按这个人调整时，以它为底稿增删改后写进 `asks`。

```json
{"title": "...", "subtitle": "...",
 "items": [{"item": "体型照片", "when": "今天 · 5 分钟", "why": "能解锁/改善什么（尽量用事实表里的数字）", "how": ["具体怎么做，一步一句"]}],
 "note": "隐私说明等"}
```

- 按"今天就能做"→"需要去医院"排序；每项写清怎么做（时间、姿势、工具、次数），做完怎么发回来。
- 常见项：体型照片（正面、侧面、背面，每月同条件）、面部照片（每季度同条件，可用于 AI 预测面部年龄和皮肤状态、看变化）、腰围、握力、7 天家庭血压、3 天饮食记录（拍每餐照片即可）、最新化验、CGM、睡眠打鼾录音或同床人观察、问卷缺项。
- 照片只用于对比和分析，说明保存在本地、可遮挡面部。
