# PRD：可扩展的 LongPi 评估架构（项目库 + 疾病风险 + 120 指数重构）

- 状态：草案，待确认
- 日期：2026-11-18
- 基线：引擎 1.1.1（分支 `feat/system-ages`，系统 LongPi Age）
- 工作分支：`feat/llm-term-registry`（基于 `feat/system-ages`）
- 版本：完成后为 1.1.2（版本号只进最后一位）

---

## 0. 一句话

把 LongPi 从"10 个写死的领域 + 1 个血液时钟 + 1 个甲基化时钟"的固定公式，改成**由 LLM 不断扩充的项目库 + 确定性合成引擎**：任何新数据（蛋白组、宏基因组、基因组、甲基化、长时序可穿戴……）都由 LLM 联网找证据、生成一条"项"，经代码核对后入库；同一个项目库同时驱动 LongPi Age、疾病风险（终身 + 当前）和 120 指数。

## 1. 目标与非目标

### 1.1 三个产品目标

| # | 目标 | 本版要做到的形态 |
|---|---|---|
| G1 | LongPi Age 更准，能整合多维数据 | 任意数据维度都能以"项"的形式接入；长时序数据让区间收窄并给出每项的变化速度；数值仍可逐项追溯到原文 |
| G2 | 120 指数用于行为引导 | 指数 = 身体状态 + 持续行为；多运动、按指南筛查等行为**当下**就能让指数变化，而不必等指标变化 |
| G3 | 疾病风险：终身 + 当前 | 每个病种同时给出 10 年风险与终身风险；基因主要抬高终身基线，已出现的异常表型抬高当前风险；已确诊的病标为"已发生" |

### 1.2 设计原则

1. **LLM 扩展公式，不代替公式。** LLM 负责读数据、找证据、生成项规格、判断重叠；数字由确定性代码合成。同一人、同一项目库版本，两次运行结果完全一致。
2. **每一岁都可解释。** 每一项列出：输入值、参考分布、效应量、出处原句、PMID/DOI、打折系数及理由。
3. **只计增量。** 新项只贡献它在已计入各项之外的信息；没有定量证据的只做定性佐证，不折成岁数。
4. **证据必须来自真实来源。** 效应量由联网检索取得，代码逐字核对"数值—原文"绑定；LLM 不得凭记忆给数值。
5. **不以回测为门槛。** 本版不新做人群数据拟合；新项用文献中多因素校正后的效应量，并保守打折。原有 NHANES 校准结果保留。
6. **两层运行环境。** 报告层离线、只读冻结的项目库、仍只依赖 Python 标准库；组学层（§5b）独立运行，可下载参考数据、可用科学计算依赖，结果缓存为标准观测。组学层不可用时报告照常出，相关数据列为"待分析"。建项（§2.2）需要联网。
7. **个人数据不出本机。** 建项时联网检索只发送指标名称、平台、结局等通用信息，绝不发送任何人的数值、基因型或文件内容。
8. **安全护栏优先于覆盖面。** 新项对单人的总贡献有上限（§4.5），宁可少计，不可让一条错项改写结论。

### 1.3 非目标

- 不做新的人群队列回测或模型训练。
- 不改 WPP 2024 生命表、Gamma 脆弱性、PhenoAge 分段校准、GrimAge 增量这些已有方法本身（只改它们的承载形式）。
- 不做诊断；疾病风险是预测，不是诊断结论。

## 2. 架构总览

```
  任意资料 ──▶ ① 读入层（LLM）──▶ 标准化观测 observations.json
                                         │
                       项目库里没有的指标 ─┤
                                         ▼
                         ② 建项层（LLM 子技能，联网）
                           检索证据 → 项规格草案 → 代码核对 → 入库/定性
                                         │
                              registry/（带版本、冻结、哈希）
                                         │
                                         ▼
                         ③ 合成层（确定性引擎，离线）
          ┌──────────────────────┬──────────────────────┬──────────────────────┐
          │ LongPi Age / 系统年龄 │ 疾病风险（10 年/终身） │ 120 指数（状态+行为）  │
          └──────────────────────┴──────────────────────┴──────────────────────┘
                                         │
                                         ▼
                         ④ 叙述层（LLM）：只引用事实表里的数字
```

### 2.1 读入层（LLM）

- 输入：任何文件（体检 PDF/照片、可穿戴导出、CGM、蛋白组/代谢组矩阵、宏基因组丰度表、基因芯片原始文件或 VCF、甲基化 β 值/IDAT、厂商报告）。
- 输出：`observations.json`，每条观测为
  `{obs_id, analyte, value, unit, method/platform, specimen, datetime, source_file, source_locator, vendor_derived: bool}`。
- 原始矩阵类数据由 LLM 选择计算工具（见 §5），工具输出也写成观测，并记录工具名、版本、系数来源。
- 原文数值由代码回到原文件逐字核对（沿用现有"化验值照报告原样"的规则）。

### 2.1b 标准编码（防止项目库重复）

每条观测和每个项都必须带标准编码，建项前先按编码查重，同一指标不建第二条：

| 类型 | 编码 |
|---|---|
| 化验 | LOINC |
| 蛋白 | UniProt + 平台探针号（SomaScan SeqId / Olink OID） |
| 代谢物 | HMDB |
| 微生物 | NCBI Taxonomy |
| 基因 / 变异 | HGNC；变异用 SPDI（ClinVar 查询不用 HGVS） |
| PRS | PGS Catalog 的 PGS ID |
| 甲基化 / 组学时钟 | 时钟名 + 原文 DOI + 系数版本 |
| 疾病 | ICD-10 |

编码由 LLM 提出、代码查官方字典校验；查不到的指标先停在"待编码"，不建项。

### 2.1c 观测的有效性

- **治疗状态**：正在用药的指标标 `treated`（降压药下的血压、他汀下的 LDL、降糖药下的血糖）。治疗下的值不能当作自然水平：状态项按"治疗后"的效应量计（证据有区分时）；无区分时按未治疗前的最近一次值计，并在报告中说明。
- **暂时状态**：把现有血检的 `clock_exclude` 推广到所有观测：急性病、孕期、剧烈运动后、非空腹、近 3 个月用过抗生素（宏基因组）、输血后（血常规）等，由 LLM 根据资料标注、代码按规则剔除或降权。
- **多来源冲突**：同一指标多个来源时的优先级：实验室测量 > 自行计算的组学评分 > 厂商报告 > 设备 > 自述；同级取时间最近；差异超过测量误差 2 倍时在报告中列出"不一致"。
- **适用范围**：用户年龄、性别、族裔落在研究人群之外时，该项效应量额外收缩（默认 ×0.7）或降为定性，由项规格 `population` 判定。

### 2.2 建项层（LLM 子技能）

触发：观测里出现项目库没有的 `analyte`（或已有项但平台/单位/人群不匹配）。

LLM 的工作：
1. 联网检索该指标与结局（全因死亡、某系统结局、某种疾病发病）的关联，优先级：荟萃分析/大型前瞻队列（≥100 例结局事件）> 孟德尔随机化 > 单中心队列。
2. 产出**项规格草案**（格式见 §3），包括效应量、校正变量列表、研究人群与族裔、检测平台、原文原句。
3. 判断与已有项的**重叠**（§4.2）。

代码的工作（`registry.verify`）：
- 抓取原文（PubMed/Europe PMC 摘要或开放全文），逐字核对 HR、CI、单位与原句一致；
- 校验字段完整、单位可换算、参考分布可用；
- 通过入库标准（§3.3）后写入项目库新版本；未通过的写入 `registry/qualitative/`，只做定性佐证。

### 2.3 合成层（确定性引擎）

沿用现有形式，项的集合改为从项目库读取：

`log R = Σ_i c_i · l_i(x_i)`，`l_i = f_i(x_i) − ln E_ref[exp f_i(X)]`，`LongPi Age = 年龄 + ln E[R] / b`

- 已有 10 个领域、PhenoAge 时钟、GrimAge 增量全部迁成项目库条目，**数值与 1.1.1 逐位一致**（验收硬条件）。
- 新项**只有测到才进入**：未测的新项不从人群抽样（否则每个人的区间都会因库变大而变宽）；"看不到的那一块"仍由现有残差项代表。
- 每一项带 `kind`：`state`（身体状态）/ `exposure`（暴露，如吸烟、饮酒）/ `behavior`（行为）/ `genetic`（先天）。不同输出使用不同子集（§6、§7）。

### 2.4 叙述层（LLM）

不变：Claude 只引用 `facts` 事实表里的数字。新增：每个新项在报告里标"新增项"，并列出出处；定性佐证单独成段，明确"不计入数值"。

### 3.1 目录

```

  MANIFEST.json                # 每个条目的哈希；运行时校验
```

### 3.3 自动入库标准（已确认采用方案 A）

同时满足以下条件，自动计入数值，报告标"新增项"：

1. 人体前瞻队列、荟萃分析或孟德尔随机化研究，结局是全因死亡或目标疾病发病；
2. 结局事件 ≥100 例，报告 HR（或 RR/OR 可换算）及 95% CI；
3. 代码核对通过：HR、CI、单位、"每多少单位"与原文原句一致；
4. 证据等级 ≥ B（等级定义沿用干预模块：A 随机对照试验/MR + 队列一致；B 大型前瞻队列或荟萃；C 小样本或横断面；D 无人体结局证据）；
5. 检测平台与用户数据一致，或有已发表的平台换算；
6. 参考分布可得（研究给出均值/SD，或指标本身已按年龄残差化）。

不满足的进入 `qualitative/`：报告里写"有研究提示……，目前证据不足以折成岁数"，不进数值。

### 3.3b 同一指标多项研究

- 同一编码、同一结局有多项合格研究时：优先已发表的荟萃分析；没有时，按随机效应合并（对数 HR 与 SE），合并过程写入 `sources/`。
- 研究间方向矛盾（一项保护、一项有害且都显著）时降为定性，不合并。

### 3.4 治理

- 运行时只读冻结版本；建项产生新版本，旧版本保留，可回滚。
- **建项是一次性的**：同一指标在所有用户间共用一条项，首次遇到时建，之后直接复用（控制联网与模型调用成本）。
- **定期复核**：每季度对全部 `active` 项检查撤稿、是否有更新的荟萃分析、原文链接是否有效；有变化的生成新版本。
- **许可**：每个项、每份参考数据、每个评分（PGS Catalog 中各评分沿用原始论文的许可，部分不允许商业使用）都记录许可；不允许商业使用的不入库。
- 每个条目可被人工标为 `retired`（停用）并写明原因；停用不删除。
- `docs/tools/gen_tech_tables.py` 扩展为从项目库生成参数总表，`--check` 校验文档与库一致。

## 4. 合成规则

### 4.1 打折系数 c_i

| 来源 | c_i |
|---|---|
| 已有 10 个领域、时钟、甲基化 | 沿用 1.1.1 的 NHANES 估计（有/无血液时钟两套） |
| 新项，研究已校正了该用户模型里所有与之相关的已计入项 | `overlap.coef` 默认 0.8（SD 0.2），只打折不放大 |
| 新项，只部分校正 | 由 LLM 按机制判断，默认 0.4–0.6，写明理由 |
| 新项，只有年龄性别校正 | ≤0.3，或直接归为定性 |

所有 c_i 带不确定度，在抽样中传播；区间因此包含"打折是否恰当"的部分不确定度。

### 4.2 重叠组（`groups.json`）

- 同一机制的多个项（例如 PhenoAge、GrimAge2、蛋白组年龄、代谢组年龄同属 `aging_clock`）：
  - 组内按"在已有项之外的信息量"排序，最强一项按 4.1 计入；
  - 其余项只有当其研究**同时校正了**排在前面的项时才计入，否则只做佐证。
- 防止"测得越多、风险被重复计越多"：组内各项 c_i 之和设上限（默认 1.2），超出按比例压缩。

### 4.3 族裔迁移

非东亚人群来源的效应量在对数尺度上收缩（默认 ×0.8），并把 SD 加宽 25%；有东亚队列的优先用东亚队列。

### 4.4 长时序（通用状态空间）

现有 PhenoAge 的局部水平卡尔曼滤波推广到每一项：

- 模型：局部线性趋势（水平 + 斜率），观测噪声 = 分析误差 + 个体内生物学变异（项规格 `measurement`；化验沿用 EFLM CVI，设备沿用品牌偏差）。
- 高频数据（手表、CGM）先按周聚合，换设备时插入设备偏差项。
- 输出：每项当前水平（进合成）、斜率及区间（进"变化速度"展示）。
- 现有 LongPi Pace 改为各项斜率经同一模型合成后的整体斜率；报告门槛不变（后验区间比先验窄 20% 以上才报告）。

### 4.5 安全护栏

- **单人上限**：所有新增项（非 1.1.1 原有项）对一个人的 log R 合计贡献限制在 ±0.30 以内（约 ±3 岁），超出按比例压缩并在报告中注明；单项上限 ±0.15。上限随项目库版本可调整，调整须写理由。
- **人群中性检查**：每个项目库新版本发布前，用合成人群（按各项参考分布抽样）检查：加入新项后人群平均 R 仍约为 1（偏差 <2%），否则该版本不发布。
- **方向检查**：每个新项写明"数值越高风险越高还是越低"，并用原文核对；与原文方向不符的拒绝入库。

### 4.6 系统年龄

沿用 1.1.1 的归组方式：每个项带 `system` 字段，系统年龄 = 年龄 + ln E[exp(Σ 该系统的项)] / b。厂商器官年龄规则不变（单独佐证行，不进系统年龄）。

## 5. 数据维度接入计划

| 维度 | 接入方式 | 预计计入情况 |
|---|---|---|
| 常规化验扩展 | ApoB、Lp(a)、hs-CRP 单列、胱抑素 C/eGFR、HbA1c、尿白蛋白肌酐比、NT-proBNP、腰围 | 计入；与 LDL、血糖、PhenoAge 内项进重叠组 |
| CGM | 均值、CV、TIR 汇总后作为观测 | 非糖尿病人群的死亡证据有限，多数先做定性；糖尿病人群 TIR 有结局证据 |
| 长时序可穿戴 | 步数、静息心率趋势、HRV、作息规律、睡眠时长 | 步数、作息规律为 `behavior` 项（§7）；静息心率、睡眠沿用已有领域；HRV 视证据 |
| 影像 | 冠脉钙化积分、颈动脉斑块、DXA 骨密度/肌肉量、肝脏弹性 | 冠脉钙化有强证据，计入；其余视证据 |
| 甲基化 | 厂商时钟值；有 β 值时用开源系数计算 | GrimAge2 规则不变；DunedinPACE 等按增量规则；商业授权的时钟只接收厂商结果，不从原始数据自行计算 |
| 蛋白组 | 平台矩阵 → 蛋白组年龄 / 器官年龄（开源系数） | 有死亡 HR 的计入 `aging_clock` 组，器官年龄带 `system` |
| 代谢组 | 平台矩阵 → 已发表的代谢组评分 | 视证据 |
| 宏基因组 | 丰度表 → 已发表的分类/功能指标 | 死亡证据少，多数定性 |
| 基因组 | 芯片/VCF → PRS、APOE、单基因致病变异 | 主要用于疾病终身风险（§6）；全因死亡层面一般不计入 |

计算工具放在 `scripts/tools/`（甲基化时钟、蛋白组时钟、PRS 计算），每个工具附系数来源与许可说明；没有可用开源系数或许可不允许的，只接收厂商结果。

## 5b. 二级数据分析（组学层）

### 5b.1 范围

- 接收**二级数据**：VCF / 芯片原始基因型、甲基化 β 值矩阵、蛋白组 NPX/RFU 矩阵、代谢组定量表、宏基因组物种或功能丰度表。
- **不接收一级数据**（FASTQ、IDAT、质谱原始文件）：比对、变异检测、峰识别不在本技能范围，提示用户向检测机构索取二级数据。
- 重新计算只在"能产生过门槛的项"时有意义：输出的每个特征都要么对应项目库里的项，要么进定性佐证；不输出没有结局证据的大量特征去充数。

### 5b.2 固定流程（每类数据一条，确定性）

| 数据 | 质控与预处理 | 计算与注释 |
|---|---|---|
| 基因组（VCF/芯片） | 识别参考基因组版本（GRCh37/38，必要时 liftover）；链方向与等位基因对齐；样本缺失率、杂合率、性别核对；芯片数据用公开参考面板（1000 Genomes / 东亚面板）填补；推断族裔（与参考人群的主成分投影） | ① PRS：PGS Catalog 东亚验证过的评分，报告位点覆盖率，低于评分要求不出分，按东亚参考分布换算分位数 ② APOE 分型 ③ 单基因致病变异：ClinVar（SPDI 查询，审核星级 ≥2，仅"致病/可能致病"），基因范围按 ACMG 次要发现推荐列表 ④ 药物基因组：按 CPIC 规则做星号等位基因判读（与现有 `pgx_rules.md` 合并） |
| 甲基化（β 值） | 探针过滤、平台识别（450K/EPIC v1/v2）、缺失探针按时钟作者的方式处理并报告缺失比例 | 开源系数的时钟；商业授权时钟只用厂商结果 |
| 蛋白组 | 平台与版本识别（SomaScan 版本、Olink 面板）；跨版本换算按官方桥接文件；批次说明 | 蛋白组年龄、器官年龄（开源系数）；单蛋白只在有结局证据时进项（如 NT-proBNP、GDF15） |
| 代谢组 | 平台识别（如 Nightingale NMR）、单位统一 | 已发表的代谢组评分 |
| 宏基因组 | 区分 16S 与宏基因组；测序深度检查；组成数据按 CLR 变换；分类数据库版本记录 | 已发表的分类或功能指标；大部分进定性佐证 |

- 每一步的工具名、版本、参考数据版本、参数写入 `results.json: provenance`；同一输入、同一版本重复运行结果逐位一致。
- 参考数据（填补面板、ClinVar、PGS 评分文件、平台桥接文件）首次下载后本地缓存并记录版本日期；ClinVar 每月更新一次。

### 5b.3 工具库（与项目库并列）

```
skills/longpi-omics/tools/
  REGISTRY.json            # 工具名、版本、输入输出、许可、验证记录
  <tool_id>/               # 代码 + 测试数据 + 预期结果
```

- 现有工具覆盖不了的分析，LLM 可以编写新工具，但入库前必须通过：① 用已知答案的公开样本跑出与原作者一致的结果 ② 同一输入运行两次逐位一致 ③ 许可允许 ④ 不联网发送任何个人数据。
- **不允许**在单次报告里让 LLM 临时写代码分析用户数据并把结果当作数值使用；未入库工具的产出最多进定性佐证。

### 5b.4 遗传结果的告知规则

- **可干预的单基因致病变异**（如 BRCA1/2、Lynch 相关基因、LDLR）：改写相关疾病的终身风险；报告中提示进行遗传咨询和临床确认检测，不在报告里给"确诊"。
- **不可干预或有心理负担的结果**（如 APOE ε4/ε4 与阿尔茨海默病）：默认不展示，用户主动选择查看后才展示，并附解释。
- 是否接收次要发现由用户在上传前选择；未选择的一律不展示。
- 意义不明变异（VUS）不展示。
- 这些规则由宿主产品的同意流程落实，本技能输出时按 `disclosure` 字段分级。

## 6. 疾病风险引擎（新模块 `scripts/lp/disease.py`）

### 6.1 模型

对病种 d：个人发病风险函数 `h_d(t) = h0_d(age_t, sex) · RR_d(t)`，`log RR_d = Σ_i c_{i,d} · l_{i,d}`，项来自同一项目库中 `outcomes` 含 d 的条目。

- **10 年风险（当前风险）**：`∫_0^10 h_d(t) · S(t) dt`，S 为同一模型下的个人生存曲线（考虑"先因其他原因死亡"）。
- **终身风险**：同式积分到 90 岁（或报告约定的终身上限）。
- 两者是**同一模型在两个时间窗上的积分**，不是两个模型。

### 6.2 基因与表型的关系

- PRS、APOE、家族史属 `genetic` 项：作用于整条风险曲线，因此主要体现在终身风险上。
- 血糖、血脂、血压等表型属 `state` 项，作用于当前水平，按 §4.4 的斜率外推若干年后衰减回人群均值（衰减速度按项规格），因此主要体现在 10 年风险上。
- **中介打折**：PRS 有一部分作用经由已测表型实现（例如 2 型糖尿病 PRS 经由血糖、BMI）。表型已测时，PRS 项的 c 用"校正了该表型后"的效应量；文献没有时默认打折到 0.5，并写明。
- **已确诊**：该病种输出"已发生"，不再给发病风险；同时把该病作为其他病种的风险项（例如糖尿病对冠心病、慢性肾病）。

### 6.3 首批病种（13 个）

2 型糖尿病、冠心病、卒中、高血压、慢性肾病、代谢相关脂肪性肝病（MASLD）、结直肠癌、肺癌、肝癌、胃癌、乳腺癌、前列腺癌、阿尔茨海默病。

### 6.4 基线发病率

- 心血管与代谢病：中国慢性病前瞻性研究（CKB）等已发表的中国分年龄性别发病率；
- 癌症：中国肿瘤登记年报的分年龄性别发病率；
- 每个病种一份 `registry/outcomes/<disease_id>.json`，含来源、年份、分年龄性别表与许可。
- 使用有非商业限制的数据源（如部分 GBD 结果）前须确认许可；默认不用。

### 6.5 输出与报告

- 每病种：10 年风险、终身风险（点估计 + 80% 区间）、同龄同性别人群对照、主要驱动项（列贡献与出处）、"已发生"标记。
- 风险卡改为"引擎出数，Claude 只写叙述"；指南阈值分级（`references/risk_rules.md`）保留，作为"关注/留意/一般"的判定规则，并与引擎数值并列。
- China-PAR 10 年心血管风险保留，作为指南口径对照。

### 6.6 基因输入

- `person.json` 新增 `genetics.raw`（芯片原始文件或 VCF 的相对路径、芯片型号、参考基因组版本）与 `genetics.vendor_scores`（厂商给出的 PRS 分位数，单独标明来源）。
- 以原始文件为主：PRS 取 PGS Catalog 中在东亚人群验证过的评分，按东亚参考分布换算成分位数；位点覆盖率低于评分要求时只报告覆盖率，不出分。
- 遗传结果的展示须经现有遗传告知同意流程（由宿主产品负责）。

## 7. 120 指数重构

### 7.1 定义（生存口径）

- **状态部分**：现有定义不变，基于 LongPi Age 的 R。
- **行为部分**：持续行为对全因死亡的效应，折算为 `R_index = R_state × Π_b exp(c_b · l_b)`；
  `120 指数 = 100 + 10·log10(P_本人(120 | R_index) / P_同龄人(120))`。
- 报告分开显示："身体状态贡献 X 分，持续行为贡献 Y 分"。

### 7.2 行为项

| 行为 | 依据形式 | 防重复规则 |
|---|---|---|
| 每日步数 | 剂量反应荟萃（Paluch 2022 等） | 已测 VO2max 时按中介比例打折 |
| 每周中高强度运动分钟、抗阻训练频次 | 队列剂量反应 | 同上；已测握力时抗阻项打折 |
| 作息与睡眠规律 | 队列证据 | 与睡眠时长领域进重叠组 |
| 戒烟时长、饮酒减少 | 已有吸烟/饮酒领域 | 已在状态部分，不重复计 |
| 按时服用已处方药物（降压、降脂） | 依从性与结局研究 | 已测血压/LDL 达标时不重复计 |
| 按指南完成的癌症筛查 | 单病种死亡 RR（如结直肠癌粪便免疫化学检测/肠镜、高危人群低剂量 CT 肺癌筛查、高危人群肝癌超声 + 甲胎蛋白、胃镜） × 该病占同龄同性别全因死亡的比例 | 只对适用人群计；泛泛的健康体检不单独加分（全因死亡证据不足） |

- 行为的认定：来自数据（手表步数、运动记录、筛查报告日期），或用户自述（自述的 c 额外打折）；需持续 ≥8 周才计入，中断后按项规格衰减。
- 预期效果：筛查类给分较小（通常零点几分），如实显示；运动、步数类给分明显，体现"做了就涨"。

### 7.3 与 LongPi Age 的关系

- LongPi Age 只用 `state` + `exposure` 项（身体现在是什么样）；
- 120 指数用 `state` + `exposure` + `behavior` 项（身体状态 + 正在做的事）；
- 行为改变后，指数立刻变化；指标随后真的变化时，状态部分上升、行为部分的中介打折同步加大，总分不重复计。

## 7b. 报告、补测清单与干预的联动

- **展示**：项可能有几十条。总览只显示贡献最大的 5 项（正负各计），其余按系统折叠；每项可展开看输入、出处、打折理由。
- **补测清单**：现有"补做某项后区间缩多少"扩展到组学与基因检测。新项未测时不进入合成，因此信息价值按该项参考分布模拟"测了以后"的结果计算；同等收益先推荐便宜的检测，不为"提高准确度"推荐高价组学。
- **干预**：每个计入的新项须标注"有没有已知能改变它的干预"（引用随机对照试验）；没有的，在报告中如实说"这一项目前只能监测"。新的干预条目同样走建项门槛。
- **不同变化速度**：长时序下每项给出自己的斜率，报告挑出"变好最快"和"变差最快"的项，作为正向反馈和提醒。

## 9. 验收

不以回测为门槛，以下全部满足才算完成：

1. **回归一致**：只含迁移后的原有项时，演示用户 D01 的 `results.json` 中 LongPi Age、区间、120 指数、系统年龄、补测清单与 1.1.1 一致（差值 <1e-9）。
2. **可复现**：同一人、同一项目库版本运行两次，结果逐位一致；`results.json` 记录项目库版本与哈希。
3. **核对率**：自动入库的新项 100% 通过数值—原文逐字核对；抽查 ≥5 条人工复核原文。
4. **恒等式**：系统年龄各项 + 余项 = 全身 log R（沿用 1.1.1 的检查）；120 指数的状态 + 行为分解与总分一致。
5. **端到端**：至少 2 位合成用户（不同性别、年龄段），资料各自覆盖常规体检多年 + 长时序可穿戴 + 至少两种组学（蛋白组、甲基化、宏基因组、基因组中任选，两人合计覆盖全部四种），从原始文件跑到 `report.html`，含建项过程。
6. **疾病风险**：13 个病种全部能出数；已确诊病种显示"已发生"；方向性检查：同一人只提高 PRS 时，10 年与终身风险都上升，且终身风险的绝对增加更多；只提高当前血糖时，10 年风险的相对增幅大于终身风险的相对增幅。
7. **行为指数**：步数从 4000 提到 9000 持续 8 周，120 指数上升且 LongPi Age 不变；此后 VO2max 实测上升时，总分不重复计（方向性检查）。
8a. **建项能力盲测**：把 1.1.1 人工整理的 10 个领域、GrimAge 当作"未知指标"，让建项子技能在看不到现有参数的情况下重新建项；效应量须落在现有参数的 95% CI 内，打折系数方向一致；至少 8/11 条通过，否则建项规程要改。
8b. **组学流程**：PRS 用公开 1000 Genomes 东亚样本与 PGS Catalog 已发表的结果对照（相关 ≥0.99）；ClinVar 注释用已知致病与已知良性位点各 ≥20 个做正反例，全部判对；基因组坐标 GRCh37/38 各跑一遍结果一致。
8c. **护栏**：构造一条效应量故意放大 10 倍的假项，确认被单项上限截住，报告中注明；人群中性检查能拦下一个故意未归一化的项目库版本。
8d. **隐私**：抓取建项环节所有外发请求，确认不含任何个人数值、基因型或文件内容。
8. **对抗审查**：多路独立审查（畸形输入、超大文件、错误单位、伪造来源、重复计数、许可）的 P0/P1 全部修完。
9. **文档一致**：`gen_tech_tables.py --check` 通过；README、CHANGELOG、技术文档、方法摘要同步。

## 13. 已知局限

- 新项的效应量来自不同研究、不同人群，打折系数由规则和 LLM 判断给出，没有在统一队列中检验。
- 组学研究多为欧洲人群，迁移到中国人群有不确定性（§4.3 只做了保守处理）。
- 疾病基线发病率来自已发表汇总表，年份与地区代表性有限。
- 行为项的中介比例多为文献估计，可能高估或低估重复计数。
